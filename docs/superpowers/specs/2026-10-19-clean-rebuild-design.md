# 포스트시즌 예매 리허설 · 전면 재작성 설계 (2026-10-19)

## 목적과 전제
- 기존 사이트는 다른 사람이 만든 공개 아티팩트 「예매 버튼 반응 연습」의 코드 위에 좌석 선택·권종·결제·예매 내역을 덧붙인 것이었다. 공모전(전국민 AI 경진대회 「AI 달인의 꿀팁 챌린지」) 제출을 위해 전체를 이 설계서만 보고 처음부터 새로 만든다.
- 구현자는 `legacy/` 아래의 기존 파일과 원본 아티팩트를 열어 보지 않는다. 이 문서가 유일한 입력이다. 변수명·id·문구·CSS 구조는 모두 새로 정한다.
- 사용자는 개발 비전문가다. 완성 후 사용자가 직접 휴대폰으로 열어 60초 세로 영상을 찍는다.

## 산출물
- `postseason-rehearsal.artifact.html`: claude.ai 아티팩트 게시용 본문. doctype·html·head·body 태그 없이 `<title>포스트시즌 예매 리허설</title>` 로 시작한다(게시 시 래퍼가 붙는다). 그 뒤에 `<meta name="claude:viewport-fit-sides" content="cover">`, 구글 폰트 `<link>`, `<style>`, 마크업, `<script>` 순서.
- `index.html`: 래퍼를 씌운 독립 실행본. `tools/build.py`(표준 라이브러리만)가 아티팩트 파일 앞뒤에 아래 래퍼를 붙여 생성한다.
  - 앞: `<!doctype html><html lang="ko"><head><meta charset="utf-8"><meta name="viewport" content="width=device-width,initial-scale=1,viewport-fit=cover"><style>:root{color-scheme:light;box-sizing:border-box}body{margin:0;padding:0;font:14px -apple-system,BlinkMacSystemFont,sans-serif;background:#fff;color:#000}img{max-width:100%}[hidden]:not([hidden=until-found i]){display:none!important}</style></head><body>`
  - 뒤: `</body></html>`
- 외부 의존성은 구글 폰트 `<link>` 만 허용한다(Inter 400/500/600, Noto Sans KR 400/500/600, Geist Mono 500/600). 스크립트 CDN 금지, 빌드 도구 없음, 이미지 파일 없음(포스터·보안문자는 캔버스로 그린다).
- 파일 크기 상한 120KB. 저장은 UTF-8(BOM 없음), 줄바꿈 LF.

## 사용 장면
- 야구·콘서트 티켓팅에서 번번이 실패하는 일반인이 휴대폰이나 PC로 실제 예매처와 비슷한 흐름을 미리 연습한다.
- 60초 세로 영상(휴대폰 화면 녹화)으로 촬영하므로 휴대폰 세로 화면(390×844)에서 가장 보기 좋아야 한다. PC(1024px 이상)에서는 예매 사이트와 연습 설정 패널이 나란히 2열이다.

## 화면 구성

### 공통 틀
- 상단 바(고정): 제품명 「포스트시즌 예매 리허설」, 설명 칩 「연습용 · 가상 예매 사이트 · 실제 결제 없음」, 버튼 「연습 시작」(주요), 「좌석 선택부터」(보조).
- 가상 예매 사이트 카드: 사이트 머리(브랜드 「Rehearsal Ticket」 + 「연습용」, 메뉴 「예매」 「예매 내역 n」, 서버시간 시계), 단계 표시(1 대기열 · 2 보안문자 · 3 좌석 선택 · 4 권종·결제 · 5 완료, 현재 단계 강조·지난 단계 완료 표시), 제한시간 바(좌석 선택부터 결제까지만 표시).
- 결과 상자와 기록 상자: 예매 사이트 카드 바로 아래.
- 연습 설정 패널(코치 패널): PC에서는 오른쪽 열(폭 약 340px), 휴대폰에서는 사이트 카드 아래에 접힌 상태(「연습 설정 펼치기」 버튼)로 둔다.

### 화면 1 · 상품(홈)
- 포스터: 캔버스 380×504 비율. 흰 바탕에 연한 파란 그라데이션과 얇은 격자, 작은 소제목 「REHEARSAL」, 큰 제목 「POST / SEASON」 두 줄, 파란 알약 라벨 「2026 · KBO 포스트시즌」.
- 경기 정보: 제목 「[연습] 2026 KBO 포스트시즌 한국시리즈 1차전」, 장소(선택한 구장), 경기일 「2026.10.31 (토) 14:00」, 예매 오픈(시작 전 「연습 시작을 누르면 카운트다운이 시작돼요」, 시작 후 「서버시간 HH:MM:SS 오픈 예정」), 관람 등급 「전체 관람가 · 인당 최대 4매」.
- 좌석 등급·가격표(아래 구역 7개).
- 안내 목록: 예매 수수료 1매당 1,000원 · 모바일 티켓 무료 / 제한시간 안내(설정값 반영: 「예매 화면 이동 후 n분 이내에 결제를 완료하지 않으면 자동으로 종료됩니다」 취지) / 취소는 예매 내역에서 가능, 연습용이라 실제 환불 없음.
- 예매 버튼: 시작 전 비활성 「판매 예정입니다」, 카운트다운 중 비활성 「남은시간 MM:SS」(1시간 이상이면 H:MM:SS), 오픈 순간 파란 활성 「예매하기」. 옆에 서버시간.
- 접속 중 오버레이: 스피너 + 「접속 중입니다」 + 「잠시만 기다려 주세요. 새로고침하지 마세요.」. 오류 시 「접속자가 많아 연결이 지연되고 있어요」 + 「잠시 후 다시 시도해 주세요.」 + 「다시 시도」 버튼.

### 화면 2 · 대기열
- 제목 「접속 인원이 많아 대기 중입니다.」, 부제 「조금만 기다려주세요.」, 상품명 줄(「[연습] 구장명 · 포스트시즌 대비」).
- 카드: 「나의 대기순서」 큰 숫자(단조 글꼴, 천 단위 쉼표), 진행 트랙(점이 왼쪽에서 오른쪽으로 이동), 「현재 대기인원」, 「예매율」.
- 안내: 제한시간 안내문, 「잠시만 기다리면 예매 페이지로 연결된다」 「새로고침하거나 재접속하면 대기순서가 초기화되어 더 오래 기다린다」 취지의 문구 두 줄(문장은 새로 쓴다).
- 연습 정보 줄: 예상 대기 n분 n초, 남은 좌석 약 n석, 그리고 내 반응 n ms · 서버 도착 오픈 후 n.nnn초 · 전체 n명 중 상위 n% 요약.
- 버튼 「새로고침 (실수 체험)」: 누르면 대기순서가 전체의 92~100% 구간으로 밀리고 기록에 「새로고침 · 대기순서 a번 → b번」이 남는다. 이후 요약 줄은 「새로고침으로 맨 뒤에서 다시 대기 중」.

### 화면 3 · 보안문자
- 제목 「화면의 문자를 입력해주세요」, 부제 「문자 입력 인증 후 좌석을 선택할 수 있습니다」 취지(문장은 새로).
- 캔버스 보안문자 6자(영문 대문자, I·O 제외), 배경 노이즈 점, 글자별 기울임·상하 흔들림, 가로지르는 곡선 1~2개. 「새 문자」 아이콘 버튼.
- 입력칸(placeholder 「화면의 문자를 입력하세요 (대소문자 구분 없음)」), 힌트 「한/영 전환을 잊어도 괜찮아요. 한글 모드로 쳐도 같은 자리의 영문 키로 바뀌어요.」
- 한글 모드 처리: 두벌식 자판의 자모·완성형 글자를 같은 자리의 영문 키로 되돌린다(ㅅ→T, 궤→RNP). IME 조합 중(compositionstart부터 compositionend까지)에는 값을 바꾸지 않고 조합이 끝난 뒤 변환한다. 영문·변환 결과만 남기고 대문자 6자로 자른다. 6자가 차면 「입력완료」 활성.
- 오답: 메시지 「문자가 일치하지 않아요. 새 문자로 다시 입력해 주세요.」, 새 문자 생성, 오답 횟수 누적.
- 연습 정보: 경과 n.n초, 남은 좌석 약 n석(입력 중에도 계속 줄어든다). 통과 시점에 남은 좌석이 0이면 실패(「입력하는 사이 남은 좌석이 모두 팔렸어요」).

### 화면 4 · 좌석 선택
- 머리: 「구역을 선택하세요」, 남은 좌석 약 n석 · 희망 n매.
- 구역 목록 7개 카드 버튼: 이름, 가격, 잔여 약 n석(0이면 「매진」 표시·비활성), 잔여 비율 바.
- 블록 화면: 「← 구역 다시 선택」, 제목 「구역명 · n블록」(블록 번호 = 100 + 구역 코드×10 + 1~8 임의), 보조 「가격 · 이 블록 140석」, 「그라운드 방향」 표시, 10열×14번 그리드(7번과 8번 사이에 통로 한 칸), 범례(선택 가능 / 판매 완료 / 내 선택), 「연석 자동배치」 버튼과 안내 「빈자리를 눌러 직접 고르거나 자동배치를 누르세요」.
- 선택 규칙: 희망 매수까지만 선택 가능, 초과 시 안내. 자동배치는 가운데 열부터 바깥으로 훑으며 통로를 넘지 않는 연석을 찾고, 없으면 「이 블록에는 n자리 붙은 좌석이 없어요」 안내.
- 선택 칩 목록(「n블록 n열 n번」), 「좌석 선택 완료 (n매)」 버튼(선택 없으면 비활성).
- 실시간 소진: 0.6초마다 전체 남은 좌석이 줄고 구역 잔여가 갱신되며, 보고 있는 블록의 빈자리도 일부가 판매 완료로 바뀐다. 남은 좌석이 0이 되면 실패(「좌석을 고르는 사이 남은 좌석이 모두 팔렸어요」).
- 좌석 충돌: 완료 클릭 시 좌석을 들고 있던 시간 10초당 약 6%(최대 60%) 확률로 고른 좌석 하나를 뺏기고 「이미 선택된 좌석이 포함되어 있어요 (n열 n번). 다른 좌석을 다시 선택해 주세요.」 안내, 기록에 남긴다.
- 단석 구간(남은 좌석이 판매분의 약 30% 아래): 블록에 붙은 빈자리가 생기지 않고, 희망 2매 이상이면 경고 문구를 띄운다.
- 블록 안 빈자리 분포는 구역 잔여 비율을 따른다(잔여가 적을수록 드문드문).

### 화면 5 · 권종
- 표: 좌석(「구역명 n블록 n열 n번」) / 권종 select(일반, 할인권 (20%)) / 가격.
- 요약: 티켓 금액, 예매 수수료(n매 × 1,000원), 배송 · 모바일 티켓 0원, 총 결제 금액.
- 버튼 「좌석 다시 선택」(선택 해제 후 좌석 화면으로, 소진은 계속), 「결제하기로 이동」.

### 화면 6 · 결제
- 양식: 예매자 이름(기본 홍길동), 휴대폰 번호(기본 010-0000-0000), 결제 수단 라디오(신용·체크카드 기본 / 간편결제 / 무통장입금), 카드사 select(연습카드 · 리허설카드 · 테스트카드)와 할부(일시불 · 2개월 · 3개월)는 카드일 때만 표시, 동의(전체 동의 + 필수 2개: 취소·환불 규정, 개인정보 제3자 제공).
- 결제 요약 상자(경기 · 좌석 · 결제 수단 · 결제 금액). 이름·전화·필수 동의가 모두 채워져야 「결제하기」 활성.
- 「권종 다시 선택」 버튼.
- 승인 중 오버레이 1.2~2.5초: 「결제 승인 요청 중」 「창을 닫거나 새로고침하지 마세요」. 설정한 실패 확률로 「카드사 승인에 실패했어요 (연습용 오류). 결제 수단을 확인하고 다시 시도해 주세요.」를 띄우고 재시도 횟수를 센다.

### 화면 7 · 완료
- 상태 배지(예매 성공 / 예매 실패), 제목(성공: 「예매가 완료되었습니다」, 실패: 사유 제목), 예매번호(성공 시, 형식 `R` + YYMMDD + `-` + 영숫자 6자, I·O·0·1 제외), 보조 문구.
- 타임라인 5칸: 반응 n ms / 대기열 n번 / 보안문자 n.n초 / 좌석 선택 n.n초 / 결제 n.n초 (없는 값은 「-」).
- 요약 섹션: 반응·서버 도착 / 대기열(구장, 나의 대기순서, 전체 n명 중 상위 n%, 입장 시 남은 좌석) / 보안문자(입력 시간·오답 횟수, 입력 중 팔린 좌석) / 좌석 선택(고른 시간, 구역·블록) / 결제 재시도 횟수 / 전체(오픈부터 완료까지 n.n초) / 실패 사유 항목(예: 매진 때 내 앞 대기 n명, 제한시간).
- 버튼 「다시 연습」 「예매 내역 보기」, 안내 「Enter 또는 R 키로도 바로 다시 연습할 수 있어요」(입력칸에 포커스가 없을 때만 동작).

### 화면 8 · 예매 내역
- localStorage 키 `rehearsal.v2.bookings` 에 저장(읽기 실패 시 빈 목록). 카드: 예매번호, 상태 배지(예매 완료 / 취소됨), 경기 · 구장, 좌석 목록, 권종 · 결제 수단 · 금액 · 예매 시각(YYYY.MM.DD HH:MM).
- 「예매 취소」를 누르면 그 자리에서 「정말 취소할까요? 취소 수수료는 연습용이라 없어요.」 + 「취소 확정」 「돌아가기」 2단계 확인.
- 비어 있으면 「아직 예매 내역이 없어요. 연습 시작을 눌러 첫 예매를 완료해 보세요.」
- 메뉴 「예매」를 누르면 진행 중이던 단계 화면으로 돌아간다(진행 중이 아니면 홈).

## 연습 설정 패널
1. 시나리오 프리셋(한 번에 여러 설정을 바꾼다): 빠른 리허설(기본: 5초 카운트다운, 접속자 몰림 켬, 10배 속도, 제한 3분, 결제 실패 0%, 규모 18만) / 실전 그대로(실제 속도, 제한 10분, 그 외 동일) / 매진 체험(3초, 규모 50만) / 결제 실패 체험(3초, 실패 100%).
2. 단계 바로가기: 대기열부터 / 보안문자부터 / 좌석 선택부터 / 결제부터. 앞 단계를 통과한 것으로 가정(반응 40~80ms, 대기순서 1,500~4,000번 임의)하고 기록에 「바로가기 · ○○부터 (반응 n ms · 대기순서 n번으로 가정)」을 남긴다. 결제부터는 1루 내야 지정석 블록에서 자동배치까지 끝낸 상태로 연다. 상단 바의 「좌석 선택부터」도 같은 동작.
3. 오픈 연습: 모드(5초 카운트다운 기본 / 3초 / 15초 / 다음 정각(:00초) / 지정 시각), 오픈 시각(time 입력, 초 단위, 기본 18:00:00; 지정 시각이 이미 지났으면 다음 날), 서버 - PC 차이(초, 소수 허용; 서버시간 = PC 시간 + 차이; 안내 「서버시간 확인 사이트에서 예매처 서버가 내 PC보다 몇 초 빠른지(+) 느린지(-) 보고 입력하세요」 취지), 「시작」 버튼과 PC 시계. 카운트다운 중에는 모드 변경 불가. 5/3/15초 모드는 0~0.4초 임의 지연을 더해 박자를 외우지 못하게 한다. 다음 정각은 지금부터 3초 이상 남은 가장 가까운 정각.
4. 구장: 잠실 23,750석(기본) / 대구 라이온즈파크 24,000석 / 수원 kt 위즈파크 18,700석 / 광주 챔피언스필드 20,500석. 진행 중에는 변경 불가. 일반 예매 판매분 = 총 좌석의 약 76%.
5. 대기열 규모: 연습용 2만 / 정규시즌 인기 8만 / 와일드카드 12.5만 / 준플레이오프 18만(기본) / 플레이오프 25만 / 한국시리즈 50만.
6. 접속자 몰림: 켜기(기본) / 끄기.
7. 내 희망 매수(인당 최대 4매): 1 / 2(기본) / 3 / 4.
8. 대기 진행 속도: 실제 속도 / 10배 빠르게(기본).
9. 좌석 선택·결제 제한시간: 10분(실제) / 3분(기본) / 60초. 홈과 대기열의 안내문에 반영.
10. 결제 실패 확률: 0%(기본) / 30% / 100%.
11. 판정 기준 안내(문장은 새로 쓴다): 반응 150ms 이하 빠름, 151~300ms 보통, 300ms 초과 늦음 / 오픈 전 클릭은 비활성 버튼이라 무시되고 횟수만 기록 / 좌석 선택을 오래 끌면 빈자리가 사라지고 고른 좌석도 뺏길 수 있음 / 규모가 클수록 박자 맞춰 누르는 숙련자가 앞을 채워 보통 반응으로는 차례 전 매진이 흔함, 전 과정 연습은 「연습용 2만」이나 단계 바로가기 / 좌석 수·대기열은 가상 시뮬레이션이며 선택한 구장 기준 연석 한계 약 n명째, 완전 매진 약 n명째(모델에서 계산해 100명 단위로 표시).

## 결과·기록 상자
- 결과: 최근 사건 한 문장(색 good / warn / bad). 통계 4칸: 최고 반응, 평균(최근 10회), 예매 완료 수, 실패 수.
- 기록: 최신이 위. 각 줄 앞에 서버시간 HH:MM:SS. 사건: 반응(n ms · 판정, 오픈 전 연타 n회), 서버 오류(n초 기다린 뒤 실패), 대기열 통과(n번 · 입장 시 남은 약 n석) / 차례 전 매진, 새로고침(순번 전 → 후), 보안문자(n초 · 오답 n회 · 남은 약 n석), 좌석 충돌, 좌석 선택(n초 · 구역 · n매), 좌석 선택 중 매진, 시간 초과, 결제 실패, 예매 완료(번호 · n매 · 금액 · 총 n초), 예매 취소, 바로가기.

## 시뮬레이션 모델(요구 수치는 아래와 같고, 수식과 자료구조는 구현자가 설계한다)
- 반응 시간 = 「예매하기」가 활성된 순간부터 첫 pointerdown까지. 서버 도착 = 반응 + 기본 지연 약 12ms + (접속자 몰림 시) 접속 지연.
- 접속자 몰림 켜짐: 접속 중 화면의 지연은 중앙값 0.2초(2만)~0.7초(50만), 긴 꼬리 최대 6초. 접속 오류 확률 0.2%(2만)~1%(50만). 오류 뒤 「다시 시도」를 누르면 그때까지 흐른 시간이 서버 도착에 더해져 순번이 밀린다.
- 접속자 반응 분포(규모 N명): 세 집단 혼합. 숙련자(박자형, 중앙 약 100ms·표준편차 약 55ms), 일반(보고 누름, 중앙 약 300ms·오른쪽으로 치우침), 지각(0.6초 뒤부터 평균 4초의 긴 꼬리). 숙련자 비율은 2만에서 약 25%, 18만 약 33%, 50만 약 45%. 대기순서 = 내 서버 도착보다 먼저 도착한 접속자 수 + 1 + 작은 임의 편차(0~40).
- 입장 속도: 초당 400명(실제 속도). 10배 모드는 시뮬레이션 시간만 10배 빠르게 흐른다(반응 시간 측정은 영향 없음).
- 좌석 소진: 입장자 1명이 평균 약 3.3매(1매 3% · 2매 20% · 3매 7% · 4매 70%, 구매 성공률 95%)를 가져간다. 판매분의 약 69%가 연석으로 먼저 빠지고, 나머지 31%는 1명당 약 1.1매의 단석으로 빠진다. 입장 시 남은 좌석이 0이면 「차례 전 매진」.
- 목표 범위(잠실 · 18만): 반응 60ms이면 대기순서 대략 2,000~6,000번(좌석 있음), 100ms이면 6,000~12,000번(단석 구간), 150ms 이상이면 대부분 차례 전 매진. 2만 규모에서는 400ms여도 대부분 통과한다. 구현 후 디버그 함수로 100회씩 돌려 이 범위를 확인하고 맞지 않으면 분포 모수를 조정한다.
- 보안문자·좌석 선택 중 소진 속도: 연석 구간 초당 150석, 단석 구간 초당 40석.
- 대기열 화면의 예매율 = (판매분 - 남은 좌석) ÷ 판매분.

## 접근성·품질
- 세그먼트 버튼은 aria-pressed, 메시지는 aria-live="polite", 입력에 label, 캔버스에 aria-label, 누르는 요소는 button 요소.
- 모든 타이머는 한 곳에서 관리해 화면 전환·재시작 때 전부 정리한다. 진행은 setInterval 기반으로 하고(배경 탭에서도 진행), 카운트다운 표시만 requestAnimationFrame을 써도 된다.
- 콘솔 오류 0. 전역 오염 없음(IIFE, 'use strict'). 디버그용으로 `window.__rehearsal = { sampleRank(ms, crowdN, seatsTotal), version }` 만 노출한다.
- 코드 구성: `<title>` → meta → 구글 폰트 링크 → `<style>` → 마크업 → `<script>` 한 블록. 함수는 역할별로 묶고 짧은 한국어 주석을 단다.

## 검증(구현자가 수행하고 결과를 보고에 적는다)
1. `python tools/build.py` 로 index.html 생성, 두 파일 크기 확인.
2. JS 문법 검사: `<script>` 내용을 추출해 사용할 수 있는 도구(node 또는 deno)로 파싱한다.
3. `python -m http.server 8765` 로 띄우고 브라우저 도구가 있으면 390px 폭으로 전체 흐름(시작 → 예매하기 → 대기열 → 보안문자 → 좌석 → 권종 → 결제 → 완료 → 예매 내역 → 취소)과 바로가기 4종, 프리셋 4종을 확인한다. 브라우저 도구가 없으면 확인하지 못한 항목을 보고에 명시한다.
4. 모델 수치: `window.__rehearsal.sampleRank` 로 60 / 100 / 150 / 400ms × 2만 / 18만 조합을 각 100회 돌려 범위를 보고한다.
