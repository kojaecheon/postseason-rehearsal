## 2. 작품 설명 (500자 안팎, 기본 문안)
포스트시즌 야구 예매에서 번번이 실패하고 나서야 알았습니다. 손이 떨려서 지는 거라면 연습을 하면 됩니다. 그런데 티켓팅은 연습할 곳이 없습니다. 그래서 AI에게 실제 예매처와 같은 흐름의 「연습용 예매 사이트」를 만들어 달라고 했습니다.

먼저 AI와 대화하며 화면 8개와 동작 규칙을 적은 설계서를 만들고, 그 설계서로 HTML 파일 하나를 생성했습니다. 카운트다운, 예매 버튼 반응속도 측정, 18만 명 대기열, 보안문자, 좌석 선택, 권종, 결제, 예매 내역까지 전부 가짜로 돌아갑니다. 새로고침하면 순번이 맨 뒤로 밀리는 실수도 미리 겪어 볼 수 있고, 한/영 전환을 깜빡해도 보안문자가 알아서 바뀝니다.

휴대폰으로 열어 몇 번 연습하면 예매 버튼이 켜지는 순간에 손이 먼저 나가고, 좌석 화면에서 머뭇거리면 자리가 사라진다는 감각이 몸에 남습니다. 개발을 모르는 기획자가 코드를 한 줄도 직접 쓰지 않고 만들었습니다.

꿀팁은 하나입니다. 떨리는 일이 있으면 AI에게 「연습용」을 만들어 달라고 하세요. 티켓팅뿐 아니라 면접, 발표, 수강신청에도 통합니다.

※ 대기열과 좌석 수는 가상 시뮬레이션이며 실제 예매처 수치와 다릅니다. 실제 결제와 개인정보 입력은 없습니다.

## 3. 작품 설명 (200자 안팎, 짧은 문안)
티켓팅에 번번이 지는 이유는 실력보다 연습 부족이었습니다. AI에게 실제 예매처와 같은 흐름의 연습용 예매 사이트를 만들어 달라고 해서, 카운트다운부터 반응속도 측정, 18만 명 대기열, 보안문자, 좌석 선택, 결제까지 휴대폰으로 미리 리허설합니다. 가상 시뮬레이션이라 실제 결제와 개인정보 입력은 없습니다. 꿀팁: 떨리는 일은 AI에게 「연습용」을 만들어 달라고 하세요.

## 4. AI 활용 과정 (단계별 항목이 있을 때)
1. 요청: 「실제 예매처처럼 긴장되는 티켓팅 연습 사이트를 HTML 파일 하나로 만들어 줘」 한 문단으로 시작.
2. 설계: AI와 질문과 답을 주고받으며 화면 8개(홈·대기열·보안문자·좌석·권종·결제·완료·예매 내역), 연습 설정 11항목, 판정 규칙(반응 150ms 이하 빠름, 300ms 초과 늦음)을 설계서로 확정.
3. 생성: 설계서만 보고 HTML 한 파일을 생성. 외부 라이브러리 없음, 이미지 없음(포스터와 보안문자는 코드로 그림).
4. 검증: AI가 휴대폰 폭 390px에서 전체 흐름을 돌려 보고, 대기열 모델을 조합마다 100회 표본으로 확인. 발견한 결함 7건(결제 동의 버튼, 글꼴 지연 등)을 수정.
5. 사용: 휴대폰으로 열어 연습하고 그 화면을 녹화.
