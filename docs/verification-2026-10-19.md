# 포스트시즌 예매 리허설 전면 재작성 검증 결과 (2026-10-19)

설계서 `docs/superpowers/specs/2026-10-19-clean-rebuild-design.md` 만 보고 새로 만든 결과물이 설계서의 검증 4항목을 모두 통과했습니다. `legacy/` 폴더, README.md, 원본 아티팩트는 열어 보지 않았습니다.

## 1. 산출물

| 파일 | 크기 | 형식 |
|---|---|---|
| `postseason-rehearsal.artifact.html` | 118,887 바이트 | UTF-8(BOM 없음), LF, `<title>포스트시즌 예매 리허설</title>` 로 시작 |
| `index.html` | 119,307 바이트 | 래퍼 앞부분 + 아티팩트 본문 + `</body></html>` |

- 아티팩트 본문 순서: `<title>` → `<meta name="claude:viewport-fit-sides" content="cover">` → 구글 폰트 `<link>` 3개(preconnect 2개, 스타일시트 1개) → `<style>` → 마크업 → `<script>` 한 블록입니다.
- 외부 의존성은 구글 폰트(Inter 400/500/600, Noto Sans KR 400/500/600, Geist Mono 500/600)뿐입니다. 이미지 파일은 없고, 포스터와 보안문자는 캔버스로 그립니다.
- `build.py` 는 BOM, CR(윈도우 줄바꿈), 첫 줄 `<title>`, 120KB 상한을 검사한 뒤 바이트 단위로 `index.html` 을 씁니다.

## 4. 브라우저 확인

### 4-1. Claude 브라우저 패널

- `preview_start` 와 `resize_window` 390×844 는 성공했습니다.
- 패널이 숨김 상태여서 화면이 그려지지 않았습니다. 스크린샷과 좌표 클릭은 계속 시간 초과가 났고, 페이지 타이머가 1초에서 1분 간격으로 늦춰졌습니다. 그래서 패널에서는 DOM 조회와 스크립트 이벤트로 아래 항목만 확인했습니다.
  - 페이지 로드, 가로 스크롤 없음(문서 폭 390px), 홈에서 예매 버튼 위치(위 487px, 아래 543px로 첫 화면 안)
  - 카운트다운 시작, 오픈 전 연타 기록, 반응 75ms 측정, 대기열 통과(5,070번, 남은 약 4,260석)
  - 한글 모드 보안문자 입력(조합 이벤트 경로)과 「입력하는 사이 매진」 실패 처리
  - 최종 빌드에서 「결제부터」 바로가기 → 「전체 동의」 → 「결제하기」 활성, 소제목 여백 22px, 글꼴 CSS 비차단 적용
  - `sampleRank` 수치(아래 5절과 같은 범위)
- 패널 콘솔에는 앱 코드 오류가 없었고, 사내망에서 구글 폰트 글꼴 파일 요청이 응답하지 않아 생긴 `net::ERR_TIMED_OUT` 13건만 있었습니다.

## 6. 검증 중 발견해 고친 결함

- 결제 동의: 「전체 동의」 를 눌러도 결제 버튼이 활성되지 않았습니다. 양식의 `input` 이벤트가 `change` 보다 먼저 검증을 돌려 전체 동의를 되돌린 것이 원인이었고, 체크박스와 라디오는 `change` 에서만 처리하도록 고쳤습니다.
- 여백: 초기화 규칙 `.ps h2,.ps h3,.ps p` 의 우선순위가 높아 소제목·완료 제목·대기순서 숫자의 여백이 사라졌습니다. `:where()` 로 우선순위를 낮췄습니다.
- 글꼴 로딩: 구글 폰트 서버가 느리면 스타일시트가 스크립트 실행을 최대 45초 막았습니다. 글꼴 CSS를 `media="print"` 로 받고 스크립트가 `all` 로 바꾸도록 해서 화면과 기능이 먼저 뜨게 했습니다.
- 설정 패널: 지정 오픈 시각 입력칸이 옆 칸과 겹쳐 두 칸을 위아래로 배치했습니다.
- PC 홈: 예매 오픈 정보가 포스터 중간 높이로 떨어져 보여 격자 행 높이를 고쳤습니다.
- 반응 측정: 화면 갱신 프레임이 늦게 오는 환경에서 반응이 실제보다 작게 잡힐 수 있어, 기준 시각이 활성 순간보다 34ms 넘게 밀리지 않게 했습니다.
- 좁은 휴대폰: 375px 이하에서 좌석 그리드가 가로로 넘칠 수 있어 380px 이하 전용 간격을 추가했습니다.

## 7. 구현자 판단

설계서에 적히지 않았거나 해석이 필요한 부분은 아래와 같이 정했습니다.

### 시뮬레이션
- 접속 지연과 순번: 접속 중 화면 시간(중앙 0.2~0.7초, 긴 꼬리 최대 6초)은 서버가 도착 순서대로 처리하는 응답 대기로 보고 순번 계산에 넣지 않았습니다. 서버 도착에는 반응 + 기본 12ms + 접속자 몰림 시 요청 구간 혼잡 지연(평균 2~8ms, 최대 40ms)만 넣었습니다. 접속 중 화면 시간을 그대로 더하면 0.5초 안팎의 무작위 값이 수십 ms의 반응 차이를 덮어서 목표 범위를 맞출 수 없기 때문입니다. 오류 뒤 「다시 시도」 를 누르면 처음 누른 뒤 흐른 시간 전체를 서버 도착에 더합니다.
- 다른 접속자 분포: 숙련자 반응(중앙 100ms, 표준편차 55ms), 일반(로그정규, 중앙 300ms), 지각(0.6초 뒤 평균 4초)은 설계서 값 그대로 두었습니다. 대신 다른 접속자에게 회선·기기 지연(로그정규, 중앙 75ms)을 더하고, 숙련자를 뺀 나머지를 일반 4 : 지각 6으로 나눴습니다. 이 조정으로 5절의 목표 범위를 맞췄습니다.
- 접속 오류 대기: 오류는 1.5~4.5초 기다린 뒤 띄웁니다. 접속자 몰림을 끄면 접속 중 화면은 0.12~0.28초만 보이고 오류는 나지 않습니다.
- 10배 속도의 범위: 대기열에만 적용했습니다. 보안문자·좌석 단계의 소진(초당 150석, 단석 구간 40석)은 실제 시간으로 흐릅니다.
- 대기열 최소 표시: 순번이 아주 앞이면 10배 속도에서 1초도 안 되어 화면이 지나가므로, 진행을 늦춰 최소 2.4초 동안 보여 줍니다. 「예상 대기」 는 실제 속도 기준 남은 시간입니다.
- 단석 구간 1명당 1.1매는 1매 90%, 2매 10%로 뽑았습니다.
- 구역 잔여: 전체 잔여 비율에 구역 인기도를 거듭제곱해 나눠서 인기 구역부터 빠지게 했습니다. 0이 된 구역은 「매진」 으로 비활성됩니다.
- 블록 빈자리: 연석 구간에서는 1~7석 묶음으로, 단석 구간에서는 붙은 빈자리 없이 흩어 놓습니다. 블록마다 0.8~1.2배의 임의 계수를 두었고, 0.6초마다 구역 비율에 맞춰 일부를 판매 완료로 바꾸며 변화가 없을 때도 30% 확률로 한 자리를 팝니다.
- 권종·결제 중에도 전체 소진은 계속되지만, 이미 고른 좌석은 확보된 것으로 봅니다.
- 좌석 충돌 확률은 가장 먼저 고른 좌석의 보유 시간 기준 `min(60%, 10초당 6%)` 입니다. 좌석 화면의 연습 정보에 현재 확률을 함께 보여 줍니다.
- 자동배치는 5·6열부터 바깥 열 순서로 찾고, 같은 열에서는 통로에 가까운 연석을 먼저 고릅니다.

### 반응 측정
- 기준 시각은 버튼이 활성된 뒤 처음 그려지는 프레임 시각이며, 34ms 상한을 두었습니다. 첫 `pointerdown` 의 이벤트 시각을 쓰고, 키보드 Enter·Space도 반응으로 인정합니다.
- 예매 버튼은 `disabled` 대신 `aria-disabled` 로 비활성을 표시합니다. 비활성 중 누른 횟수(오픈 전 연타)를 세기 위해서입니다. 오픈 전 연타는 카운트다운 중에만 셉니다.
- 바로가기에서 가정한 반응은 최고·평균 반응 통계에서 뺍니다.

### 화면과 동작
- 휴대폰 홈: 포스터(폭 120px)와 경기 제목·장소·경기일을 나란히 두고, 예매 오픈·관람 등급을 아래 줄에, 예매 버튼을 가격표보다 위에 두었습니다. 390×844에서 예매 버튼 아래 끝이 553px입니다.
- 상단 바와 사이트 머리는 휴대폰에서 각각 2줄입니다(제품명·버튼 / 설명 칩, 브랜드·서버시간 / 메뉴 탭).
- 1023px 이하에서는 1열이고 설정 패널을 접어 둡니다. 설계서는 760px 이하만 정했지만 761~1023px도 2열을 넣기 좁아서 같은 방식으로 처리했습니다.
- 「연습 정보」 는 사이트 안에서도 연한 주황 점선 상자로 구분해 실제 예매처 화면이 아니라는 점을 드러냈습니다.
- 접속 중·결제 승인 오버레이는 화면 전체를 덮는 고정 대화상자로 만들었습니다.
- 화면이 바뀔 때 사이트 카드 위쪽이 화면 밖이면 카드 맨 위로 즉시 이동합니다.
- 잠금: 카운트다운 중에는 오픈 방식·지정 시각·서버 차이·프리셋을, 진행 중(카운트다운부터 완료 전까지)에는 구장을 바꿀 수 없습니다. 규모·접속자 몰림·대기 속도·제한시간은 다음 연습부터, 희망 매수와 결제 실패 확률은 바로 반영됩니다.
- 지정 오픈 시각 입력을 바꾸면 오픈 방식이 「지정 시각」 으로 자동 전환됩니다.
- 매진 체험·결제 실패 체험 프리셋에서 설계서에 적히지 않은 값(접속자 몰림 켬, 10배, 제한 3분 등)은 빠른 리허설과 같게 두었습니다.
- 결제 동의는 새 연습마다 해제된 상태로 시작합니다. 이름·전화는 유지하고, 브라우저 자동완성은 끕니다.
- 「예매 내역 n」 의 숫자는 취소되지 않은 예매 수입니다. 완료 화면 뒤 메뉴 「예매」 를 누르면 홈으로 돌아갑니다.
- 완료 화면에서 버튼에 포커스가 있을 때 Enter는 그 버튼의 동작을 따릅니다(중복 실행 방지). R은 입력칸에서만 막습니다.
- 「남은 좌석 약 n석」 은 100석 이상일 때 10석 단위로 반올림합니다. 기록은 최근 80줄까지 보관합니다.
- 결과 상자의 안내성 문장은 기본색, 사건은 good·warn·bad 색으로 표시합니다.

## 8. 확인하지 못한 것과 알려진 한계

- 실제 휴대폰(iOS Safari, Android Chrome)의 터치와 한글 키보드 IME는 확인하지 못했습니다. IME 처리는 합성한 조합 이벤트로만 확인했습니다.
- Claude 브라우저 패널이 숨김 상태여서 패널에서 화면을 직접 보고 누르는 확인은 하지 못했습니다. 화면 확인은 헤드리스 Chrome 스크린샷으로 대신했습니다.
- claude.ai 아티팩트로 게시한 상태(iframe, 게시용 래퍼, localStorage 차단 가능성)는 확인하지 못했습니다. localStorage 를 쓸 수 없으면 빈 목록으로 시작하고 그 화면 안에서만 내역을 유지하도록 작성했습니다.
- 「콘솔 오류 0」 은 앱 코드 기준입니다. 로컬 확인에서는 favicon.ico 404와 사내망의 구글 폰트 시간 초과가 네트워크 오류로 기록되었습니다. 글꼴이 늦게 오면 기본 글꼴로 먼저 보였다가 바뀝니다.
- 카운트다운 숫자는 requestAnimationFrame 으로 그려서 탭이 가려진 동안에는 숫자가 멈춰 보일 수 있습니다. 오픈 자체는 타이머로 정확한 시각에 일어납니다.
- 모델 꼬리: 요청 구간 혼잡 지연의 긴 꼬리 때문에 18만·60ms에서 드물게 6,000번을 넘고(100회 중 최대 7,375번), 18만·100ms에서 드물게 12,000번을 넘습니다(최대 13,372번).
- 반응이 300ms 안팎이면 18만 규모에서는 거의 항상 차례 전 매진입니다. 60초 영상에서 전 과정을 보여 주려면 「연습용 2만」 이나 단계 바로가기를 쓰는 편이 안정적입니다.
- 파일 크기가 상한 120KB에 가깝습니다(120,000바이트 기준 여유 약 1.1KB). 기능을 더하면 상한을 넘을 수 있습니다.
- 380px 이하 화면에서는 좌석 칸이 20px보다 작아질 수 있습니다(320px에서 약 17px). 가로 스크롤을 막는 쪽을 우선했습니다.
