# 포스트시즌 예매 리허설

연습용 가상 예매 사이트. 카운트다운 → 예매하기 → 접속 중 → 대기열 → 보안문자 → 구역·좌석 선택 → 권종 → 결제 → 완료 → 예매 내역·취소까지, 실제 예매처와 비슷한 흐름을 휴대폰이나 PC에서 미리 연습한다. 실제 결제와 개인정보 입력은 없다.

## 파일
- `postseason-rehearsal.artifact.html`: 아티팩트 게시용 본문. `<title>` 로 시작하고 doctype·head·body 래퍼가 없다(게시 시 래퍼가 붙는다). 고칠 때는 이 파일만 고친다.
- `index.html`: `tools/build.py` 가 위 파일 앞뒤에 래퍼를 붙여 만든 독립 실행본. 직접 고치지 않는다.
- `tools/build.py`: 빌드 스크립트(표준 라이브러리만). BOM·윈도우 줄바꿈·첫 줄·120KB 상한을 검사한 뒤 `index.html` 을 쓴다. 실행: `python tools/build.py`
- 외부 의존성은 구글 폰트(Inter, Noto Sans KR, Geist Mono)뿐이다. 포스터와 보안문자는 캔버스로 그린다. 파일 크기 상한 120KB까지 여유가 약 1KB뿐이라 기능을 더하면 CSS나 문구를 줄여야 한다.

## 연습 흐름과 설정
- 화면: 홈(포스터·경기 정보·가격표·예매 버튼) → 접속 중 오버레이 → 대기열(나의 대기순서·현재 대기인원·예매율·새로고침 실수 체험) → 보안문자(영문 대문자 6자, 한글 모드로 쳐도 같은 자리의 영문 키로 변환) → 좌석 선택(구역 7개 → 10열×14번 블록, 연석 자동배치, 실시간 소진, 좌석 충돌) → 권종(일반·할인권 20%, 수수료 1매당 1,000원) → 결제(모의 승인 1.2~2.5초, 실패 확률 설정) → 완료(예매번호·단계별 소요 시간·요약) → 예매 내역(이 브라우저에만 저장, 취소 2단계 확인).
- 연습 설정 패널(PC는 오른쪽 열, 휴대폰은 아래쪽 접힘): 시나리오 프리셋 4종(빠른 리허설 · 실전 그대로 · 매진 체험 · 결제 실패 체험), 단계 바로가기 4종(대기열 · 보안문자 · 좌석 선택 · 결제부터), 오픈 방식(5/3/15초 카운트다운 · 다음 정각 · 지정 시각)과 서버 - PC 시간 차이, 구장 4곳, 대기열 규모 6단계(연습용 2만 ~ 한국시리즈 50만), 접속자 몰림, 희망 매수 1~4매, 대기 진행 속도(실제 · 10배), 좌석 선택·결제 제한시간(10분 · 3분 · 60초), 결제 실패 확률(0 · 30 · 100%).
- 판정: 반응 150ms 이하 빠름, 151~300ms 보통, 300ms 초과 늦음. 오픈 전 클릭은 무시되고 횟수만 기록된다.
- 바로가기는 앞 단계를 통과한 것으로 가정한다(반응 40~80ms, 대기순서 1,500~4,000번). 좌석 선택 화면에서는 초당 약 150석씩 줄어 약 20초 뒤에는 붙은 자리가 거의 없어지므로, 구역 선택과 자동배치는 빠르게 끝내야 한다.

## 시뮬레이션 수치(잠실 23,750석 기준, 조합마다 100회 표본)
좌석 수와 대기열은 가상 시뮬레이션이며 실제 예매처 수치와 다르다. 일반 예매 판매분은 총 좌석의 약 76%로 본다.

| 대기열 규모 | 반응 | 대기순서 범위 | 통과율 |
|---|---|---|---|
| 2만 | 60ms | 175~296 | 100% |
| 2만 | 400ms | 7,610~7,999 | 100% |
| 18만 | 60ms | 2,316~7,375 | 100% |
| 18만 | 100ms | 7,434~13,372 | 75% (단석 구간) |
| 18만 | 150ms | 19,297~30,068 | 0% |
| 18만 | 400ms | 79,841~85,361 | 0% |

처음부터 끝까지 완주하는 연습은 「연습용 2만」이나 단계 바로가기를 쓴다. 18만 이상에서는 반응 150ms를 넘으면 대부분 차례 전에 매진된다.

## 알려진 한계
- 실제 휴대폰의 터치와 한글 키보드는 아직 확인하지 않았다(조합 이벤트는 흉내 내어 확인).
- 구글 폰트를 못 받는 환경(오프라인·사내망 차단)에서는 기본 글꼴로 보인다. 동작에는 영향이 없다.
- 탭이 가려진 동안에는 카운트다운 숫자가 멈춰 보일 수 있다. 오픈 자체는 정확한 시각에 일어난다.
- 380px보다 좁은 화면에서는 가로 넘침을 막는 쪽을 택해 좌석 칸이 20px보다 작아진다.
- 예매 내역은 브라우저 저장소에만 있다. 저장소를 쓸 수 없는 환경이면 그 화면 안에서만 유지된다.

## 영상 자동 제작(2026-10-27)
- `tools/video/`: 설치된 Chrome 을 헤드리스로 띄워 사이트 장면을 1080×1920 으로 찍는 녹화기(`recorder.js`, CDP 스크린캐스트 + ffmpeg), 장면 대본(`scenes.js`: 매진 체험 · 프롬프트 재연 · 18만 대기열 · 2만 완주 · 마무리 카드), 재연 페이지(`prompt.html`, `endcard.html`), 내레이션 생성(`tts.ps1`, 윈도우 한국어 음성 Heami), 합성(`assemble.py`: 구간 자르기 · 자막 입히기 · 내레이션 섞기).
- 실행 순서: 서버 8765 기동 → `node tools/video/scenes.js all` → `python tools/video/assemble.py`. 결과는 `tools/video/out/final_*.mp4`, 제출본은 `docs/video/`.
- 녹화 때는 앱 상단 바를 숨기고 위쪽 80px 를 자막 띠로 쓴다. 보안문자 답은 캔버스 fillText 를 가로채 읽는다(녹화용 페이지에만 주입, 사이트 코드 변경 없음).
